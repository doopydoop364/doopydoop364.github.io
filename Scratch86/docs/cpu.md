# CPU (v0.1)

Real-mode x86 core with 8/16/32-bit operand and 16/32-bit address forms. All
logic is Scratch blocks generated by `src/cpu/*.py`.

Not implemented (raise #UD, never a silent NOP): x87/FPU escapes D8-DF, protected-mode and system
instructions (LGDT LIDT MOV CRn LMSW ARPL LAR LSL ...), CPUID, RDTSC, CMPXCHG8B, MMX/SSE, SALC/ICEBP,
0F 1F hint NOPs, LOCK validity checking, CPU-profile gating (8086/286/386/486 differences).
The CPU is **not yet an 80386**: no protected mode, paging, or V86.

## Exceptions
`cpu_fault(vec)` / `cpu_trap(vec)` record a pending exception; the faulting helper returns early and the
handler re-checks `FAULT_PEND` before changing architectural state. `cpu_step` then calls `exc_deliver`:
real-mode IVT vectoring (push FLAGS, CS, IP as 16-bit values, clear IF and TF, load vector*4). Faults push
the address of the faulting instruction (prefixes included), traps/`INT` the next instruction. Implemented:
#DE (DIV/IDIV/AAM, quotient overflow), #DB (TF single-step), #BP, #OF (INTO), #BR (BOUND), #UD, #SS/#GP for
real-mode segment-limit violations (hidden limit 0xFFFF, so a word at offset 0xFFFF or a 32-bit effective
address above 0xFFFF faults, as on Intel parts; QEMU does not check this).
Debug aid, not hardware: if a vector's IVT entry is 0000:0000 the CPU stops with the red fault banner
(`diag: stop CPU when exception vector is unset`, default on) instead of running the zero page. A fault
while pushing the frame stops the CPU (shutdown). There is no double-fault vector in real mode.

## REP string instructions
One iteration executes per `cpu_step`; EIP is rewound to the start of the instruction (prefixes included)
until the count reaches zero or the REPE/REPNE condition fails. Consequences: restartable after faults
and interruptible between iterations; each iteration counts as one retired instruction.

## State and conventions
* GPRs: list `GPR` in encoding order EAX ECX EDX EBX ESP EBP ESI EDI (+ a constant zero item). Unsigned 32-bit.
* Undefined flags: MUL/IMUL set SF ZF PF from the low half, AF=0; DIV/IDIV leave all flags unchanged; shifts compute OF/CF from the architectural formulas for every count and leave AF unchanged; BT*/BSx leave the other flags unchanged except as documented. Tests mask these flags (never trusting the oracle for them).
* Flags: separate 0/1 variables `CF PF AF ZF SF TF IF DF OF` + `EFLAGS other bits`; packed on PUSHF/display.
* AF after AND/OR/XOR/TEST is set to 0 (architecturally undefined). The differential tests do not mask it, and agree with Unicorn.
* `INC`/`DEC` preserve CF. Faults stop the CPU (`CPU_STATE=3`, EIP = faulting instruction) and show a red banner; exception vectoring arrives in v0.2.
* Segment base is `selector*16`; hidden-base list `SEGBASE` is in place for protected mode.
* Reset (`cpu_reset`): architectural state (CS:EIP F000:FFF0, EDX=0x303). v0.1 has no BIOS ROM, so `machine_boot_test` (power-on / Reset button) enters a documented test configuration: flat 0000:xxxx, image from `BOOT_IMAGE` loaded at 0000:7C00, SP=7C00, A20 untouched (off by default).
* Arithmetic: 32-bit values are exact in doubles; sums/differences < 2^34. Bitwise ops use a 256x256 byte-AND table (OR/XOR derived: `a|b=a+b-(a&b)`, `a^b=a+b-2(a&b)`). No floating-point approximation is relied on.

## Scheduling
`cpu_run_batch(n)` (a warp custom block) runs <= n instructions and stops early on halt, fault, or a pending `REQ`. All loops are inside warp procedures: a loop in a normal Scratch script advances only one iteration per frame. UI scripts never touch CPU state; they set `REQ`, which the main loop consumes between batches.
